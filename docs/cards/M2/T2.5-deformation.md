# T2.5 Deformation (W, worktree `w`, ≈ 4 AD)

**Inputs:** research 03 §4.4, 06 §5.6 (RutStamp 18 B, integer kernels), `CanonData\v1\reference\deform\calls.json` (10,000 seeded `rut`/`brush` calls with reference hashes, M0), oracle `js/world.js:137-420`, `WorldGrid` (`DeltaUm`), terrain chunks (M1), `Backroads.Deform.IStampSink` (on main).

**Steps**
1. Integer µm `StampKernels`: `Rut`, `Brush`, `Relax` (`CutBlade` and deposits stubbed for M7) on `DeltaUm`, Q12 falloff table, berm share by integer divide with the remainder spread in a fixed order (06 §5.6).
2. `RutStamp` (18 B, `Pack = 1`), frozen as a contract (draft ADR-003): the sink quantises the JS arguments to a stamp, then applies the stamp, so every machine applies the same integers.
3. Implement `IStampSink` and register it in `StampSinks.Current` when Millbrook loads.
4. `DirtyRectQueue`, partial terrain-chunk updates (no full rebuilds), tree re-snap after ground changes.

**Done when:** EditMode `Deform.MatchesJs` (the 10,000 reference calls replayed in order; max height error ≤ 0.5 mm over the first 1,000 calls and ≤ 2 mm over all 10,000, reported as a curve; displaced volume ±2 %), `Deform.SubMmConverges` (0.3 mm-per-call ruts reach JS's target depth within 1 %), `Deform.Deterministic` (same stamp log → identical tile hashes, Burst on and off).

**Gate:** M2 lane (the three Deform tests).
