# T3.1 World size from the manifest; the old Millbrook becomes the test world (W, worktree `w`, ≈ 3 AD)

**Inputs:** ADR-006 §1 and §4, ADR-001 (CanonData v1 frozen), `WorldGrid.cs` (`N`, `VN`, `Half`, `TintN` are
compile-time today), `ColliderGrid.cs` (`Cells = 64`), the terrain chunker, `BuildCli.Scenes`, the M2 autotests.

**Steps**
1. `WorldGrid` takes `VN`, `Cell`, `Half` and `TintN` from a `WorldGridLayout` read from the world's manifest (v1:
   2,049 / 0.5 / 512 / 129; Millbrook: 4,097 / 0.5 / 1,024 / 257). Burst jobs get the layout as a struct field; no
   static size is left. `ColliderGrid.Cells` and the chunk count follow the layout.
2. Rename the scene `Millbrook.unity` → `CanonTestWorld.unity` (it still loads CanonData v1); every scenario, test
   and `BuildCli.Scenes` entry that named it moves (for I: the build scene list and `gates.json` via "For I").
   Client builds keep it as a Dev-only scene from M3 on; the M2 route test and every parity test run there.
3. Keep v1 bit-identical: the probes, the deformation references and the golden traces must give the same numbers as
   before the change (same hashes, same trace deltas).

**Done when:** every EditMode, PlayMode and M2 autotest passes unchanged on `CanonTestWorld`; a synthetic 4,097² layout
(flat, with a ramp) passes `WorldGrid` probe tests and a deformation smoke test at both corners; Perf: the step cost of
`heightAt`/`rayTerrain` is within 5 % of M2.
